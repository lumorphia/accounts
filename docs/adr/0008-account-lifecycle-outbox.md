# ADR-0008: 退会と復旧の状態を送信待ちの表で配送する

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-07 |
| Deciders | t1nyb0x    |

## Context

A1.4 ではサービスだけの退会と Lumorphia 全体の退会を扱う。サービスが停止中でも要求を受理し、復旧や物理削除を正しい順序で知らせる必要がある。画像は復旧しない。

## Decision

- 利用者の行を `FOR UPDATE` し、状態変更・セッションと OAuth トークンの失効・画像削除要求・通知の投入を同じトランザクションで確定する。アップロードの確定も同じロックを使う。
- 全体退会は `users.deleted_at`、独立したサービス退会は `service_memberships.deleted_at` に持つ。全体復旧で独立した退会を取り消さない。両方あるときは早い期限を通知する。管理者の全体退会は受け付けない。
- 復旧は退会から 30 日未満。~~全体は認証後のセッション作成 hook、サービスは認可コード交換または本人の復旧 API で行う。~~ 復旧の契機は [ADR-0011](0011-explicit-recovery.md) で「本人の操作だけ」に置き換えた。期限ちょうどでは復旧しない。サービスの期限切れ後の再利用は `purged`、`active` の順に通知する。
- 利用先は新しい OIDC クライアント metadata と既存の認可・トークンから記録する。通知はサービス内で増加する revision を持ち、登録された各 client audience に送る。
- `account_events` と `asset_deletions` は利用者への FK を持たない。物理削除後も未完了の配送・画像削除を続ける。完了した記録は 30 日後に消す。
- pg-boss の独立 worker が毎分と起動時に処理する。未配送の前の revision がある間は後の revision を送らない。行ロックと `SKIP LOCKED` で複数 worker の同時配送を避ける。
- 通知は固定された HTTPS の受信先への form POST。既存の EdDSA / JWKS 鍵を使い、専用 `typ` と audience、最大 120 秒の JWT を試行ごとに署名する。eventId は再試行でも同じ。2xx を受付として記録し、それ以外は 1 分から最大 6 時間の間隔で送り直す。
- 受信側は platform の検証器と必須の DB アダプターを使う。状態、revision、重複排除、セッション失効、画像削除投入を原子的に適用する。ログイン時にも UserInfo で accounts の最新の active 状態を確認する。
- `FEATURE_ACCOUNT_LIFECYCLE=0` を既定にし、新規退会と worker を止める。既に退会した利用者の復旧は止めない。本番の起動と監視、利用サービスの DB アダプターは後続段階で接続する。

## Consequences

退会の受付と各サービスでの適用は非同期になる。未配送の通知がある間は後の状態を保留し、監視で滞留を拾う必要がある。外部への送信中は DB の行ロックを保持する。再試行を終了させないため、受信先の廃止や client の変更では古い受信先への対応が必要になる。

サービスは期限切れのローカルデータを再ログイン時にも先に削除し、通知の遅れで旧データを復旧しない。画像は削除要求から除外せず、同じ画像を再アップロードしても旧キーを再使用しない。
